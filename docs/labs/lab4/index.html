    Лабораторная работа 4. Машинное обучение: предсказание дефолта по кредиту

    Описание задачи

    Цель лабораторной работы — изучить построение моделей бинарной классификации и освоить метрики оценки их качества. В качестве задачи выбрано предсказание дефолта по кредиту: по анкетным данным заёмщика определить, допустит ли он просрочку более 90 дней.

    Данные взяты из соревнования Kaggle Give Me Some Credit.

    В ходе работы требовалось:

    • загрузить и исследовать набор данных из CSV-файла;
    • заполнить пропуски в данных;
    • обучить модели логистической регрессии и случайного леса;
    • провалидировать модели на тестовой выборке;
    • сравнить метрики качества: accuracy, confusion matrix, ROC-AUC;
    • в самостоятельной части — улучшить Random Forest и сравнить с SVM, kNN и градиентным бустингом.

    Исходные данные

    Набор данных содержал 50 000 обучающих и 37 500 тестовых записей. Каждый объект описывается 10 входными признаками и целевой переменной — наличием просрочки более 90 дней (SeriousDlqin2yrs).

    Признак Описание
    RevolvingUtilizationOfUnsecuredLines Доля использованных лимитов по кредитным картам
    age Возраст заёмщика
    DebtRatio Отношение долговой нагрузки к доходу
    MonthlyIncome Доход в месяц
    NumberOfOpenCreditLinesAndLoans Количество открытых кредитов и кредитных линий
    NumberRealEstateLoansOrLines Количество ипотек и кредитов на недвижимость
    NumberOfTime30-59DaysPastDueNotWorse Просрочки 30–59 дней за последние 2 года
    NumberOfTime60-89DaysPastDueNotWorse Просрочки 60–89 дней за последние 2 года
    NumberOfTimes90DaysLate Просрочки более 90 дней за последние 2 года
    NumberOfDependents Количество иждивенцев в семье

    Дисбаланс классов значительный: только 6,7% клиентов имеют дефолт (3 343 из 50 000).

    Как была решена задача

    Использованные библиотеки: pandas, numpy, matplotlib, seaborn, scikit-learn.

    1. Загрузка и анализ данных

    Данные считывались функцией pd.read_csv(). Метод .info() показал наличие пропусков в двух столбцах:

    • MonthlyIncome — заполнен в 40 147 строках из 50 000 (~80%);
    • NumberOfDependents — заполнен в 48 667 строках из 50 000 (~97%).

    Метод .describe() позволил выявить аномальные значения: максимальное значение дохода составляло 3 008 750, а ряд признаков просрочки имели значения 98, что, вероятно, означает особый код вместо реального числа дней.

    2. Заполнение пропусков

    Пропуски заполнялись средними значениями, рассчитанными по обучающей выборке:

    train_mean = training_data.mean()
training_data.fillna(train_mean, inplace=True)
test_data.fillna(train_mean, inplace=True)

    Средние обучающей выборки использовались для заполнения пропусков и в тестовых данных — это имитирует реальные условия, когда при работе модели исторические данные недоступны.

    3. Обучение базовых моделей

    Обучались две модели:

    • Логистическая регрессия (LogisticRegression, max_iter=1000) — обобщённая линейная модель, адаптированная для задачи классификации;
    • Случайный лес (RandomForestClassifier, n_estimators=100, random_state=42) — ансамбль деревьев решений.

    4. Валидация и метрики качества

    Accuracy

    Accuracy (доля правильных предсказаний) сравнивалась с константным классификатором, который всегда предсказывает 0 (нет дефолта). Поскольку 93,3% клиентов не имеют дефолта, константный классификатор уже имеет accuracy ~93%.

    Accuracy логистической регрессии оказалась близка к константному классификатору — это типичная проблема несбалансированных датасетов: модель научилась предсказывать только большой класс.

    Confusion matrix

    Матрица ошибок (confusion matrix) позволила увидеть реальное распределение предсказаний по четырём категориям:

    Предсказано 0 Предсказано 1
    Фактически 0 TN (истинно отрицательные) FP (ложная тревога)
    Фактически 1 FN (пропуск цели) TP (истинно положительные)

    Для задачи кредитного скоринга особенно опасны FN (пропущенные дефолты): банк выдаёт кредит клиенту, который его не вернёт.

    Вероятности и порог классификации

    Метод predict_proba() возвращает вероятности принадлежности к классу. По умолчанию порог классификации равен 0.5, но его можно менять:

    • Высокий порог (0.7): меньше ложных тревог, но больше пропущенных дефолтов;
    • Низкий порог (0.3): меньше пропущенных дефолтов, но больше ложных тревог — банк чаще отказывает честным клиентам.

    Выбор порога зависит от бизнес-задачи: что обходится дороже — невозврат кредита или потеря честного клиента.

    ROC-AUC

    ROC-кривая показывает зависимость TPR (доля верно найденных дефолтов) от FPR (доля ложных тревог) при изменении порога. AUC — площадь под этой кривой:

    • 0.90–1.00 — отлично;
    • 0.80–0.90 — хорошо;
    • 0.70–0.80 — удовлетворительно;
    • 0.50–0.60 — случайное угадывание.

    Самостоятельная часть

    1. Улучшенный Random Forest

    Базовый Random Forest плохо справляется с несбалансированными классами. Параметр class_weight="balanced" заставляет модель уделять больше внимания редкому классу (дефолт):

    better_random_forest = ensemble.RandomForestClassifier(
    n_estimators=300,
    max_depth=12,
    min_samples_leaf=5,
    class_weight="balanced",
    random_state=42,
    n_jobs=-1
)

    ROC-AUC улучшенного леса оказался заметно выше, чем у базового.

    2. Сравнение с другими моделями

    Были протестированы три дополнительные модели:

    SVM (метод опорных векторов) с RBF-ядром и class_weight="balanced". Требует стандартизации признаков, поэтому завёрнут в Pipeline вместе с StandardScaler:

    svm_model = Pipeline([
    ("scaler", StandardScaler()),
    ("svc", SVC(C=1.0, kernel="rbf", probability=True,
                class_weight="balanced", random_state=42))
])

    kNN (метод k ближайших соседей) с n_neighbors=15. Также требует стандартизации, чувствителен к масштабу признаков.

    HistGradientBoostingClassifier — быстрый градиентный бустинг из sklearn, работает непосредственно с пропусками и показывает хорошее качество без сложной предобработки:

    hgb_model = HistGradientBoostingClassifier(
    max_depth=8,
    learning_rate=0.05,
    max_iter=300,
    random_state=42
)

    HistGradientBoosting показал наилучший ROC-AUC среди всех протестированных моделей, что соответствует общей закономерности: на табличных данных градиентный бустинг, как правило, превосходит и линейные модели, и случайные леса.

    Нюансы решения

    Дисбаланс классов

    Только 6,7% клиентов имеют дефолт. Из-за этого модель, обученная без учёта дисбаланса, склонна предсказывать 0 для всех объектов — и получать при этом высокую accuracy. Поэтому для несбалансированных задач accuracy — плохая метрика; нужно смотреть на ROC-AUC, F1-меру или confusion matrix.

    Пропуски как сигнал

    Нулевые значения в «Год реновации» в lab5 — аналог ситуации с MonthlyIncome здесь: отсутствие данных само по себе может нести информацию (например, нет дохода = нет официального трудоустройства). Простое заполнение средним сглаживает этот сигнал.

    Порог классификации и бизнес-логика

    В задаче скоринга математически оптимальный порог 0.5 не всегда совпадает с бизнесом оптимальным. Если потери от невозврата в 10 раз выше потерь от отказа честному клиенту, оптимальный порог сдвигается вниз. Именно поэтому в реальных системах скоринга порог настраивают под конкретные бизнес-параметры.

    SVM медленнее на больших выборках

    SVM с RBF-ядром имеет сложность обучения O(n²)–O(n³) по числу объектов. На 50 000 примерах это уже заметно: обучение занимает значительно больше времени, чем Random Forest или бустинг. При увеличении выборки разрыв только растёт.

    Pipeline для предобработки

    Использование Pipeline гарантирует, что масштабирование признаков для SVM и kNN выполнялось только по обучающим данным, а тестовые данные трансформировались с теми же параметрами. Без Pipeline легко случайно «утечь» информацию из теста в обучение.

    Выводы

    В ходе работы освоен полный цикл построения классификатора: от обработки несбалансированных данных с пропусками до сравнения нескольких моделей по ROC-AUC. Ключевые выводы:

    • Accuracy — ненадёжная метрика при дисбалансе классов; ROC-AUC даёт объективную картину.
    • Параметр class_weight="balanced" существенно улучшает качество Random Forest на несбалансированных данных.
    • HistGradientBoosting показал лучший ROC-AUC среди всех протестированных моделей.
    • Выбор порога классификации — бизнес-решение, а не техническое.
