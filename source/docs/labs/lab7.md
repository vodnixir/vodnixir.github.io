# Лабораторная работа 7. Анализ текста: классификация твитов по тональности

## Описание задачи

Цель работы — изучить инструменты обработки естественного языка на примере задачи бинарной классификации **тональности твитов** (позитив / негатив). В ходе работы требовалось:

- освоить понятие n-грамм и векторизацию текстов через `CountVectorizer` и `TfidfVectorizer`;
- сравнить разные представления текста (униграммы, биграммы, триграммы, пентаграммы, символьные n-граммы);
- использовать токенизацию `nltk` и удаление стоп-слов;
- познакомиться с лемматизацией через `pymorphy3`;
- провалидировать `LogisticRegression` и сравнить с двумя альтернативными моделями (`XGBClassifier`, `LinearSVC`);
- разобраться, почему наивные пайплайны на этих данных дают «идеальную» accuracy = 1.0.

## Исходные данные

[RuTweetCorp](http://study.mokoron.com/) - корпус русскоязычных твитов с автоматической разметкой по тональности: позитивные размечены по наличию `)` / `:D`, негативные — по `(` / `:(`. После объединения получилось **226 834 твита** (≈51% позитив, 49% негатив), разбитых на train/test через `train_test_split` (170 125 / 56 709).

## Как была решена задача

Использованные библиотеки: `pandas`, `numpy`, `scikit-learn`, `nltk`, `pymorphy3`, `xgboost`.

### 1. Baseline: CountVectorizer на униграммах

```python
vectorizer = CountVectorizer(ngram_range=(1, 1))
X_train = vectorizer.fit_transform(x_train)
clf = LogisticRegression(max_iter=1000, random_state=42).fit(X_train, y_train)
```

Получили **accuracy = 0.77**, размер словаря — 243 823 уникальных слова. Это и есть отправная точка.

### 2. Эксперименты с n-граммами

| Представление | Accuracy | Комментарий |
|---|---|---|
| `CountVectorizer (1, 1)` — униграммы | **0.77** | базовый результат |
| `CountVectorizer (3, 3)` — триграммы | 0.64 | редкие тройки слов в test не встречаются в train |
| `TfidfVectorizer (1, 5)` | 0.75 | весь спектр от уни- до пентаграмм |
| `TfidfVectorizer (2, 2)` | 0.71 | биграммы хуже униграмм |
| `TfidfVectorizer (3, 3)` | 0.64 | recall negative падает до 0.45 |
| `TfidfVectorizer (5, 5)` | 0.56 | recall negative падает до 0.11, модель скатывается к мажоритарному классу |

Чем длиннее n-грамма, тем меньше шанс встретить её одновременно в train и test, и тем хуже обобщение.

### 3. Токенизация и стоп-слова

```python
from nltk.tokenize import word_tokenize
from nltk.corpus import stopwords
from string import punctuation

noise = stopwords.words('russian') + list(punctuation)
vec = CountVectorizer(ngram_range=(1, 1), tokenizer=word_tokenize, stop_words=noise)
```

`word_tokenize` корректно отделяет пунктуацию (например, в `исправлять:(` получаем три токена `исправлять`, `:`, `(`), удаление стоп-слов и пунктуации убирает шум. Результат — **accuracy = 0.78**, лучший «честный» результат во всей работе.

### 4. Утечка через смайлики

Если **не удалять** пунктуацию и оставить токены `(` и `)` во входных признаках, accuracy внезапно становится равен **1.00**. Это не магия модели, а утечка разметки: датасет автоматически размечен по смайликам, и они же попадают во входные фичи. То же самое происходит с символьными n-граммами `analyzer='char'` — среди символов есть скобки.

Проверка: простой бесмодельный классификатор «есть `(` → негатив, есть `)` → позитив» даёт **accuracy = 0.97**. Любая модель, имеющая доступ к этим символам, обучается на разметку, а не на смысл.

### 5. Лемматизация через pymorphy3

```python
from pymorphy3 import MorphAnalyzer
morph = MorphAnalyzer()
morph.parse('платили')[0].normal_form  # 'платить'
```

`pymorphy3` приводит словоформы к лемме (`платили → платить`, `пишут → писать`). Польза: разные формы одного слова перестают быть отдельными признаками, а стоп-слова в нормальной форме легче отфильтровать.

## Самостоятельная часть

### Сравнение классификаторов на одинаковых TF-IDF признаках

В качестве признаков — `TfidfVectorizer(ngram_range=(1,1), max_features=20000)`.

| Модель | Accuracy | f1 macro |
|---|---|---|
| LogisticRegression | **0.77** | 0.77 |
| XGBClassifier (lr=0.1, n_est=1000, max_depth=5, hist) | 0.73 | 0.73 |
| LinearSVC | 0.74 | 0.74 |

На разреженных bag-of-words признаках линейные модели (`LogisticRegression`, `LinearSVC`) опередили градиентный бустинг. Это типичная картина: TF-IDF создаёт очень высокоразмерное разреженное пространство, в котором почти линейная зависимость хорошо ловится линейными моделями, а деревья решений тратят бюджет глубины на отдельные слова.

### Параметры XGBClassifier

Использовались параметры из задания: `learning_rate=0.1`, `n_estimators=1000`, `max_depth=5`, `min_child_weight=3`, `gamma=0.2`, `subsample=0.6`, `colsample_bytree=1.0`, `objective='binary:logistic'`, `tree_method='hist'`. Метки кодировались `LabelEncoder`, так как XGBoost требует числовые классы.

## Нюансы решения

### Почему длинные n-граммы по отдельности — плохо

Биграммы и триграммы дают сигнал только если конкретная пара/тройка слов встречается и в обучении, и в тесте. На твитах с их короткой длиной и разнообразием это случается редко: словарь биграмм и триграмм почти не пересекается между выборками. Поэтому работающая практика — использовать диапазон вроде `(1, 2)` или `(1, 3)`, где униграммы дают основу, а биграммы добавляют немного контекста.

### Почему пунктуация — самый важный сигнал в этом датасете

Эмодзи `(` `)` `:D` `:(` — это не просто шум: это разметка. Удалять их нужно не «потому что так делают», а чтобы оценить настоящее качество модели. Эксплоративный анализ перед обучением — обязателен; без него можно радоваться accuracy = 1.0 и не понимать, что модель ничему не научилась.

### LinearSVC vs LogisticRegression

`LinearSVC` решает ту же линейную задачу, что и логистическая регрессия, но с другой функцией потерь (hinge вместо log). На этих данных разница между ними меньше, чем разница в выборе признакового представления.

## Выводы

1. Лучший «настоящий» результат — `CountVectorizer + word_tokenize + stopwords` в связке с `LogisticRegression`: accuracy 0.78.
2. Изолированно длинные n-граммы (биграммы и тем более пятёрки) ухудшают качество — слишком мало совпадений между train и test.
3. Удаление пунктуации в этом датасете критично: без него любая модель с доступом к скобкам обучается на разметку, а не на смысл.
4. На разреженных bag-of-words представлениях линейные модели побеждают градиентный бустинг.
5. Самые жирные приросты дают предобработка и токенизация, а не усложнение модели.
